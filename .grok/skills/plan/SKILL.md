# PLAN

## Procedure
1. State the objective and user-visible outcome.
2. Identify constraints, invariants, affected components, and compatibility concerns.
3. List likely files/modules and the data/control flow.
4. Define acceptance criteria and failure behavior.
5. Define the tests and verification commands required for completion.
6. Identify risks and explicit decision points.

## Output
- Objective
- Scope
- Architecture fit
- Change plan
- Tests
- Gates
- Risks
- Out-of-scope discoveries

Do not produce implementation claims before code exists.
