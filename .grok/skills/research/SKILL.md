# RESEARCH

Use when external evidence can materially improve an engineering decision.

## Procedure
1. Define the exact engineering question.
2. Search official documentation and source code first.
3. Inspect relevant GitHub implementations, issues, tests, and release notes.
4. Use current web/X research as leads, then verify claims independently.
5. Compare assumptions, architecture, license, maturity, and operational constraints against the current repository.
6. Report findings as VERIFIED / OBSERVED / INFERRED / PROPOSED.

## Reference families
Use mature projects as pattern libraries when relevant: coding agents, local-first databases, sync engines, memory systems, voice providers, security tooling, and agent workflow frameworks.

## Rules
- Never copy a pattern without checking its assumptions and license.
- Never treat social-media hype as authoritative evidence.
- Prefer current sources for APIs, versions, capabilities, and security information.
